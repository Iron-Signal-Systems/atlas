# Security Policy

## Reporting a Security Issue

Please do **not** report suspected vulnerabilities through public GitHub issues.

If you believe you have found a security issue in Atlas, report it privately to the project maintainer.

Include, where possible:

* a clear description of the issue;
* affected component or file;
* steps to reproduce;
* expected and observed behavior;
* potential security impact; and
* any supporting logs, traces, or proof-of-concept details.

Please avoid including real customer data, credentials, secrets, or other sensitive information.

## Project Status

Atlas is currently pre-release and under active development.

Security behavior, interfaces, schemas, and implementation details may change before a supported release.

## Disclosure

Please allow reasonable time for investigation and remediation before publicly disclosing a reported vulnerability.

Validated security issues will be addressed according to their severity and impact.

## Scope

Security reports relating to Atlas source code, build processes, infrastructure collection components, source parsing, transport, backend services, database handling, generated topology, protected access, or other Atlas-controlled components are welcome.

Issues in third-party products or infrastructure that Atlas does not control should normally be reported to the applicable vendor.
